# Epic 02 — ui-kit documentation (hybrid)

Status: **implemented** — branch `epic/02-kit-docs`  
Branch: `epic/02-kit-docs`  
Depends on: Epic 01  
Owners: `apps/editor` + `libs/ui-kit` (Storybook static build)

Parent: [docs/roadmap.md](../roadmap.md)

## 1. Goals

1. Ship an **in-app documentation hub** for `@sandbox/ui-kit` on Nuxt
   pages (overview, foundations, component catalog with live demos).
2. Keep **Storybook** as the interactive deep dive: embed or link static
   Storybook under `/docs/storybook` in production; in dev, link to
   `http://localhost:4400`.
3. Avoid duplicating every Storybook story as Nuxt pages — native pages
   cover orientation; Storybook covers controls / a11y / variants.

## 2. User stories

- As a developer, I open **Документация** from the sidebar and see an
  overview of the kit, design tokens, and components.
- As a developer, I interact with live `UiButton` / `UiToggleGroup` /
  `UiThemeSwitcher` demos on native pages (same tokens as the app).
- As a developer, I jump into Storybook for full controls without leaving
  the product shell (iframe or new tab under `/docs/storybook`).

## 3. Content model

Native docs (suggested routes under `/docs`):

| Route | Content |
|-------|---------|
| `/docs` | Hub: what the kit is, how to import, links |
| `/docs/foundations` | Colors, radii, typography; `SHAPE_CATALOG`; `TEXTURE_LIST` |
| `/docs/components` | Index of the six `Ui*` components |
| `/docs/components/[name]` | Live demo + props table (autogenerated or hand-written) |
| `/docs/storybook` | Static Storybook host **or** redirect/iframe to `:4400` in dev |

Data sources (do not invent a second catalog):

- `SHAPE_CATALOG`, `TEXTURE_LIST` / `TEXTURE_DEFINITIONS` from ui-kit
- `palette` / `tokens` from `libs/ui-kit/src/tokens`
- Component props from TypeScript exports / Storybook autodocs as
  reference while writing tables

## 4. UI

- Docs pages use the default layout from Epic 01; optional secondary
  docs nav (overview / foundations / components / Storybook).
- Live demos import components from `@sandbox/ui-kit` directly.
- Theme from shell applies to docs pages via existing `data-theme`.
- Storybook integration:
  - **Prod**: `nx run ui-kit:build-storybook` → copy/serve under
    Nuxt `public/` or a Nitro route for `/docs/storybook`.
  - **Dev**: page explains how to run `pnpm storybook` and/or iframes
    `http://localhost:4400` when available.

## 5. Files to touch (expected)

- `apps/editor/app/pages/docs/**` — hub, foundations, components
- `apps/editor/app/components/docs/**` — demo wrappers, props tables
- `libs/ui-kit/package.json` / Nx — ensure `build-storybook` is runnable
- CI or `package.json` script to build Storybook into a known output dir
- `apps/editor/README.md` + root README — docs routes
- Optional: thin ui-kit helpers that export prop metadata if tables are
  painful to maintain by hand

## 6. Tests

- Docs pages render without runtime errors (smoke / mount demos).
- At least one live demo has a component test (e.g. button click still
  works in docs wrapper).
- Storybook static build succeeds in CI or documented local script.

## 7. Definition of Done

- [x] Sidebar → Документация opens the hub
- [x] Foundations page shows token / shape / texture visuals
- [x] At least button, toggle, and theme switcher demos work live
- [x] Storybook is reachable via `/docs/storybook` (static or documented
      iframe / link) without a second repository
- [x] Green lint / typecheck / test / build

## 8. Out of scope

- Replacing Storybook with MDX-only docs
- Documenting editor domain APIs (`SceneDocument`, renderers)
- Furniture catalog or planner feature docs
- Full i18n of docs (Russian copy is fine to match the app)
